## 1. The most important finding: the agent never saw Phases 4–9

The project's custom instructions, as delivered into this session's context, were **truncated
partway through Phase 3** — the last visible content was Phase 3's third deliverable item (the
wiring/schematic requirement), followed by a literal `…[truncated]` marker. Phases 4 through 9
(tiered sourcing with per-component reasoning, the BOM table skeleton, the Component Notes
block, code shared-standards, the Phase 7 final-package order, the Phase 8 self-improvement
loop, and Phase 9 GitHub publishing) were **not present in context at all**.

This matters more than any individual content gap below, because it explains nearly all of
them: the agent designed the doorbell using only Phases 1–3, plainly stated in that partial
text, and had no way to know Phases 4–9 existed or what they required. Every gap in §2 traces
back to this, not to a prompt-wording problem.

**This is a delivery/context-length issue, not a prompt-content issue** — worth checking how the
project's custom instructions get loaded into a session (character/token limit on the "project
instructions" field, a copy-paste truncation, etc.), separately from anything about the prompt
text itself.

## 4. Proposed v1.7 patch (content changes only — not applied yet)

Per Phase 8's own process, a short patch rather than a full reprint. Pending your confirmation
before writing this into `/prompts` or bumping `<current_version>`:

- **Phase 3, `verify_before_writing`**: append — *"Show the runtime estimate explicitly:
  battery capacity (mAh) ÷ average current draw (mA) = expected hours/days. Show resistor math
  as the formula used, not just the resulting value (e.g. `(Vcc − Vf) / If = R`)."*
- **Phase 4, `sourcing_rules`**: append — *"If a search returns only listing/search-result
  pages rather than an extractable price, open one specific product page before falling back
  to a labeled estimate."*
- **Phase 5**: prepend to the `<format>` block — *"Use the skeleton below exactly — per
  component, not per whole build — even when a bundled-tier table feels more natural to write."*
- **`platform_reference` → ESP32/ESP8266 family → `alt_brands`**: add *"Wemos/Lolin (D1 Mini —
  extremely common, lowest-cost reliable ESP8266 dev board)"*.
- **New note, top of file or `global_constraints`**: *"If this prompt appears to have been
  truncated when pasted into the host platform's custom-instructions field (check for a
  `<changelog>`/`<version_control>` block — if it's missing, phases were likely cut), say so to
  the user rather than silently proceeding on a partial instruction set."* — a self-check the
  agent can plausibly perform even without knowing why it happened.

I did not apply this patch or touch any file in `/prompts`, `CHANGELOG.md`, or `README.md` —
