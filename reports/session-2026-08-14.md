## 1. Version-by-version changes (v1.0 → v1.6)

These are the actual prompt changes, as recorded in `CHANGELOG.md` and each versioned file's
own internal `version_control` block. Full text of every version now lives in
[`/prompts`](../prompts).

- **v1.0** (2026-08-08) — Initial creation: the full idea-to-build workflow (intake → clarify
  → design → tiered sourcing → BOM → code → testing checklist → self-improvement loop),
  three-tier material recommendations, and Arduino code generation standards.

- **v1.1** (2026-08-08) — Static prompt-engineering review pass (no live testing yet). Added a
  `why_this_matters` block giving the agent stakes/context for getting designs wrong,
  consolidated scattered safety/completeness rules into one `global_constraints` block, added
  a worked example to anchor the "state assumptions vs. ask a clarifying question" boundary,
  added a literal BOM table skeleton, and added explicit handling for out-of-scope ideas,
  conflicting constraints, and tiers that genuinely converge to one option.

- **v1.2** (2026-08-08) — Live test pass against the real Anthropic API, 8 cases. Found and
  fixed two real bugs surfaced by those tests: (1) test T08 showed the model correctly
  honoring a user's request to skip the BOM while still holding the safety line — the
  prompt's own rule was wrong to bundle those as equally non-negotiable, so
  `hard_non_negotiable` and `droppable_on_explicit_request` were split apart. (2) Test T07
  showed the self-improvement loop (Phase 8) never actually firing, because it demanded a
  full prompt reprint immediately after a long technical rebuild and kept getting crowded
  out — reordered to log the lesson first, and default to a short patch instead of a full
  reprint. Also added a length-discipline rule after T01/T03/T07 ran out of room before
  finishing the code section.

- **v1.3** (2026-08-08) — Added Phase 9 (GitHub Publishing & Shareables): the agent offers to
  push prompt updates and finished builds to a repo when it has git tooling, or hands over
  ready-to-paste file content otherwise, plus an optional non-cringe shareable blurb with
  hype-filler language explicitly banned.

- **v1.4** (2026-08-09) — Added a `platform_brand_reference` block naming real manufacturer
  brands (Arduino, Espressif, STMicroelectronics, Raspberry Pi Ltd, plus Nordic/TI/Microchip
  as chip-level brands), so board recommendations point to checkable brands instead of
  generic chip-family names.

- **v1.5** (2026-08-09) — Added a `reasoning_requirement` to Phase 4 and a "Component Notes"
  block to Phase 5's output format: every component recommendation now includes 2-4 relevant
  specs and one line of checkable reasoning per tier, instead of a bare part-and-price row.

- **v1.6** (2026-08-09) — Full multi-platform expansion: Arduino, ESP32/ESP8266, RP2040
  (Pico), STM32, and Raspberry Pi (Linux SBC), each with correct pin-naming conventions and
  platform-appropriate code generation (Arduino-style C++ / native STM32 HAL / Python).
  Renamed from "Arduino Idea-to-Build Agent" to "CircuitForge — Idea-to-Embedded-Build
  Agent." Merged the flat brand list into a fuller `platform_reference` with a selection
  heuristic per platform family.

  **Important caveat, corrected in this session:** v1.6's own internal changelog entry
  states it is *"Untested — recommend a live-test pass before relying on this."* The
  external `README.md` and `CHANGELOG.md` had incorrectly stated v1.6 was live-tested
  against an STM32 case, a Raspberry Pi case, and a platform-ambiguous case, with all three
  passing. That claim did not match the prompt file's own record and has been corrected in
  both external files — see §4.
